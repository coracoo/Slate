# 经验总结：拉片 vs 逐帧复刻（白模/Previs 工作法）

经过多部片子（买瓜对白、蜘蛛侠奇观、海街日记三人对话）的实践，沉淀出两条路线和一堆教训。

---

## 一、两条路线的本质区别

| | **拉片（Breakdown）** | **逐帧复刻（Rotomation / 1:1）** |
|---|---|---|
| 目标 | **理解**镜头语言，提取可复用的拍摄方法 | **对齐**参考画面，复刻某段的具体构图 |
| 产出 | 结构化分镜（景别/运镜/机位/节奏/台词/动作） | 代理与原片逐镜/逐帧重合 |
| 精度 | 镜头级（每镜在干什么、怎么拍） | 镜级→帧级（代理在屏幕哪个位置） |
| 服务对象 | 拍新片、喂 AI 视频提示词 | 复现既有镜头、当 AI 图生视频的首帧结构 |
| 底板 | 不需要原片当背景 | **原片就是镜头（底板）** |
| 一句话 | "这场戏该怎么拍" | "这一格画面对不对得上" |

**关键认知**：拍新片/出概念 → 用拉片；要和某段原片构图一致 → 用复刻。两者不要混。

---

## 二、白模（Previs）到底该干什么

- 白模的唯一职责：**锁机位、走位、轴线、景别、切点节奏、人物关系**。
- 白模**不负责美学/氛围/美术**——想让灰模"好看"是死路，它只会变成噪声。
- 美学交给 **AI 关键帧概念图 + 图生视频**（这是 AI 的强项，别用 3D 硬拼）。
- 结论：**功能（3D/2D 白模）与美学（AI 概念图）分开**。

### 形态选择（实测）
- **对话/短剧/走位/正反打/越肩** → **2D 投影引擎**最好：直接出 MP4、确定性、可批跑、JSON 驱动。
- **奇观/环境即镜头主体**（城市飞跃、大场面） → 白模拼环境必然乱糟糟，**直接交给 AI 概念图**，白模最多纯剪影算相机运动。
- Three.js 3D：对白场景过度设计、奇观又拼不过 AI，性价比最低；只有"真需要三维空间运动（环绕/俯冲）给人看调度"时才值得。

## 三、拉片的标准动作（镜头级）

1. **接触印片**（每秒1帧）看全片结构。
2. **自动切点检测**（帧差/直方图）给候选，再密集抽帧**人工归并**成叙事节拍。
3. 逐镜记录：时间码、**景别、运镜、机位（前景/后景）、台词归属、动作、出场人物**。
4. 结构化成 **storyboard JSON（唯一数据源）**，派生白模 / md / xlsx / AI 提示词。

**硬信息必须从原片读，不能猜**：切点时间、每镜时长、景别（广角/特写）、**台词是谁说的**、谁在画左/画右。

---

## 四、逐帧复刻的正确姿势

1. **不要用自建 3D 世界去"复现镜头"**——这是死路。镜头由**原片底板**决定，代理对齐到底板屏幕空间。
2. **先镜级，后帧级**：AI 图生视频只需要镜级一致（切点、时长、景别、前景是谁、轴线），不需要帧级 roto；帧级是给"替换同镜头素材"用的。
3. **对齐顺序（非常重要）**：
   - 先排 **blocking（人物空间关系）**：谁左谁右、谁最近最大、围什么道具；
   - 再定 **机位**：前景/后景、高/低、远/近、朝哪看；
   - 最后才是动作细节。
   - 构图看着不对，**先查人物调度，不是查相机朝向**。
4. 拿参考图用网格**读屏幕坐标**（nx, ny, 占屏大小 size），不要凭空填世界坐标。
5. 尺度/主次：最近的人最大、最远的人最小；广角里主体小（尺度反差），特写才怼大。

---

## 五、协作纪律（血泪教训）

- **一次只改被要求的那一镜**；已确认的镜头**绝对不能动**。改 A 镜连带把 B 镜搞坏是最严重的问题。
- 不自作主张扩展修改范围；用户说"只改 0–2s"就只动 0–2s。
- 不瞎猜——拿参考帧、读网格、量切点，再动数据。
- 白模反复"差一点"时，停下来想清楚是**方法问题（2D vs 3D、拉片 vs 复刻）**，不是继续盲调参数。
- 每改一步**抽帧自检**，用原图并排对照，再交付。

---

## 六、给 AI 短片的推荐管线

```
原片
 ├─ 拉片 → 分镜 JSON（景别/运镜/台词/动作）
 │          ├─ 对白/关系镜头 → 2D 白模锁机位/正反打/轴线
 │          └─ 奇观/环境镜头 → AI 关键帧概念图（别用白模拼环境）
 └─（需要复刻具体构图时）参考底板 + 镜级对齐 → 首帧结构
        ↓
   关键帧概念图（每镜一张，带美学）+ 运镜提示词
        ↓
   图生视频（Seedance/可灵）成片
```
