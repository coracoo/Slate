# 演员表演层契约（actor-context-v1）

演员层是对白分镜的可选扩展。分镜 JSON 仍是唯一事实来源：镜号、台词、时长、机位、景别、走位、场景和道具归属由分镜锁定，演员 agent 只能补充镜内可见的表演。

## 上下文

在分镜顶层使用 `acting_context` 保存已审核的连续性上下文，不覆盖 `actors`、`shots` 的原字段：

- `continuity_id`：当前分支；`continuities[]` 中每项有 `id`、`initial_state`。
- `facts[]`：剧情事实，含稳定 `id` 与 `text`。事实默认对角色不可见，只有事件把事实加入角色的 `known_facts` 后才可见。
- `events[]`：有 `id`、`continuity_id`、`order`、`deltas[]`。事件只允许引用已声明事实和人物；同一事件 ID 只按一次归并。
- `actor_cards`：按角色 ID 保存 `personality`、`goal`、`relationship`、`expression_rules`、`arc_stage`、`source` 和 `locked_fields`。角色卡来源可追溯，未知字段不得放入锁定列表。
- `notes`：人工补充的表演记忆。缺失状态保持 unknown，不能由 agent 猜测。

`state_at(context, continuity_id, event_ids)` 按事件顺序生成快照；跨分支事件、未知事件和无效 ID 直接报错。`visible_context` 只返回角色自己的已知事实。分镜可选 `acting_beats[]` 或 `beat_after_event_ids[]` 为镜内节拍声明 `after_event_ids`，系统为每个 beat 计算独立可见上下文；承认事件前不会提前看到事件后的事实。

## 表演草稿

候选文件位于 `创作/表演草稿_<分镜名>/`，正式分镜只在人工审核后写入：

```json
{
  "status": "ready",
  "packet": {
    "shot_id": "S1",
    "actors": [{
      "actor_id": "a",
      "evidence_fact_ids": [],
      "beats": [{
        "at": 0,
        "duration": 1.2,
        "intent": "压住情绪",
        "posture": "肩背保持不动",
        "gaze": "短暂移向手机",
        "gesture": "拇指收紧",
        "expression": "下颌轻绷",
        "voice": "低声",
        "evidence_fact_ids": []
      }]
    }]
  }
}
```

`at + duration` 必须完整落在镜头 `dur` 内且为有限数值；`actor_id` 必须在该镜请求中；beat 的 `evidence_fact_ids` 必须属于该 beat 时点的允许事实集合。若 beat 带 `after_event_ids`，事件必须在请求的允许事件中。表演输出不得包含或修改 `dur`、`cam`、`pos`、`look`、`move`、`lines`、`staging` 等固定字段，也不得新增台词、角色、伤势、服装或持物变化。

### 节拍时间角色（time_role，E07）

每个 beat 可选 `time_role`，受控词表：`start`（开始状态）、`beat`（动作关键点）、`end`（结束状态）、`compose`（构图参考）。`actor_runtime.perform` 生成草稿时按节拍顺序默认打标：首拍 `start`、末拍 `end`、中间拍 `beat`，单拍镜头标 `end`（与图片模式取末拍的旧行为一致）；按 `at` 稳定排序后打标，乱序输出也得到正确首末拍。允许人工在分镜 JSON 上改标——打标只发生在生成时，应用候选不会重标。

消费规则：图片模式编译（`prompt_compiler._image_beats`）优先取 `end` 拍作为最终姿态，全部未标时维持取末拍；视频首帧/尾帧槽位（`production_requests._check_frame_time_role`）只接受 `start`/`end` 角色的已采用关键帧（`shot["keyframe"]["time_role"]`，人工在分镜 JSON 上标注），`end` 图禁止当首帧——结束图≠开始状态，把结束图当首帧模型会被迫倒推动作。旧数据无 `time_role` 即未分类：兜底放行并打警告日志，不阻断。

模型输出先解析再校验；截断、解析失败、越界、知识泄漏、未知角色和固定字段变更均为 invalid，最多一次程序纠错。语义自检只产生 warning，不能替代程序校验。

## 应用和编译

候选记录 `run_id`、`source_revision`、`input_hash`、`source_hash`、`shot_ids`、模型参数和结果。应用使用 revision 乐观锁，只更新选择的未锁定镜头；重复应用同一 run 幂等，过期候选返回冲突。状态写入顶层 `acting_status`，值包括 `pending`、`context_ready`、`ready`、`stale`、`locked`、`invalid`。

所有创作出口调用 `prompt_compiler.compile_shot`：

- `baseline`：原分镜提示词和台词。
- `style`：只使用已审核的 style 表演候选。
- `stateful`：使用当前有效表演候选和角色卡。

来源变化会使表演候选 stale 并回退 baseline，同时保留 warning；图像按时间角色取拍（优先 `end` 拍，未标角色时取末拍），视频按时间顺序保留节拍。`voice_notes` 仅在出口声明 `supports_audio=true` 时才进入可执行音频参数，否则独立返回并提示不支持。

## 校验命令

```text
python -m unittest discover -s workbench/tests -p test_actor_*.py -v
python previs_system/tools/validate_dialogue.py <分镜.json>
```

演员层不要求真实模型才能完成结构回归；真实生图、生视频效果需在供应商能力和预算确认后单独登记，不能用离线文本登记冒充效果提升。
