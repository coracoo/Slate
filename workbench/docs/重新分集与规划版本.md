# 全剧扩写、改写与工作候选

## 操作

1. 在剧本页填写全剧目标集数，点击「扩写 / 改写」。已有大纲、分集、正文和素材设定始终作为修订依据；新故事通过新建项目创作。
2. 「扩写分集」用于增加集数，已有分集框架与正文保留，只生成新增集。修改要求可补充新增剧情的方向。「改写分集」用于调整已有剧情、重排或缩集，必须填写修改要求。
3. 生成任务在独立工作候选目录执行，当前分集和设定继续可用。页面只显示最近一次工作候选，不提供规划历史列表。
   失败后在该候选预览中点击「继续生成」，沿用同一候选、原目标和修改要求；已保存内容保留，只补未完成部分。当前正式内容发生变化后，旧候选不可续跑。
4. 核对候选的主线、分段及「保留 / 改写 / 新增 / 移出」分集清单与文件差异，点击「采用此规划」。采用时一次覆写当前规划，生成完成不会自动采用。
5. 未改变的分集保留正文；变化集的旧正文继续保留并标记待核对，新正文在确认设定后生成。已经沉淀的正文保留单文件快照，可在正文历史中查看；不提供整套规划恢复。

## 存储与边界

- 工作候选保存于项目 `剧本/.work/规划/<候选号>/`，`内容/` 内保存修订所需的分集、大纲、埋线、制作规则、构想、正文及人物/场景/道具档案。它是未采用稿，不是第二套正式规划。
- 采用时保留既有单文件 `.versions` 快照。以前已经保存的 `剧本/.versions/规划/` 目录留在本地，仅读取其中的正文历史，不迁移、不删除，也不提供整体采用或恢复入口。
- 素材 ID、人物身份、已有设定、图片、音色绑定和人工保护字段保持。修订不批量重写已有设定；只补实际引用资产的设定缺项。
- 生成失败不替换当前规划。生成期间当前内容发生变化，候选仍可查看，但禁止覆盖新修改。
- 骨架与分集卡分开生成，分集卡每批最多 3 集；集号、概要和节拍经过校验后才保存。分集阶段失败立即停止，不继续生成素材设定。
- 分段归属由已保存骨架与本批集号确定，程序统一写入 `arc_id`；模型负责剧情内容。续跑优先校验诊断中完整的同批响应，语法损坏、长度截断、缺集或内容缺项的响应不能复用。
- 旧大纲、分集卡、正文片段、伏笔和被引用资产的行为设定进入模型上下文；资产目录用于复用身份，新实体才建档。
- 扩集在代码层保护既有分集框架；全剧分段可以调整归属，既有事件、正文和伏笔坐标不被重新生成。改写以分集框架字段比较决定正文是否保留，变化集需重新扩写。
- 候选目录 `内容/剧本/规划诊断/` 保存每次模型响应、调用阶段、输出字符数、终止原因和校验错误，便于区分语法错误与长度截断。诊断不进入正式规划。
- 多文件采用与素材提交共用事务锁和恢复日志，写入失败整批回滚。采用时仅实际变化的集进入待复核范围。媒体文件保留。

## 接口

- `POST /api/units/build`：保留 `stage=replan` 兼容名称；`revision_mode=extend|rewrite|auto`，`revision_instructions` 为修改要求，`planning_source=idea|script` 为补充来源。`auto` 在增加集数时采用扩写，其余采用改写；已有故事基线始终传入。
- 同一接口传入 `stage=replan` 与 `planning_version=<失败工作候选号>` 即续跑；不新建候选，不重做已保存骨架与有效分集，不允许重复启动正在生成的候选。
- `GET /api/units/candidate`：返回当前工作候选与正式规划 `revision`；携带 `id` 返回该候选与当前正式稿的逐文件差异。
- `POST /api/units/edit`：`kind=adopt-plan`，携带当前工作候选 `id` 和预览时取得的 `revision`。`restore-plan` 与旧历史候选采用请求均拒绝。
- `GET /api/units` 的旧 `planning_versions` 字段保持空列表。工作候选记录保存修订方式、修改要求及逐集变化；旧候选不能覆盖最近一次修订。
