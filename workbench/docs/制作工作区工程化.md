# 制作工作区

## 业务评估

- 剧本的建库、补缺、扩集和改写曾作为多个平级入口展示，用户难以判断输入与覆盖范围。统一为规划操作选择，正文生成与改写共用候选流程，审核后采用。
- 角色文本分散在素材、设定和演员页面，声音又有独立入口。角色工作区负责全剧资料；镜内表演仍保存在分镜，避免修改全剧人物时覆盖已审核镜头。
- 平面推演和 3D 白模不适合成为每个项目的强制工序。空间明确的镜头直接创作，存在轴线或路径问题时用 2D，存在遮挡、透视或机位问题时用 3D。
- 提示词存在输出格式与补充规则冲突、未采用表演流入生成、静帧混入连续动作等问题。按输出契约、剧情事实、角色背景、创作方法、画风分层处理，并在执行端校验。
- 工程化不是删除全部模板：用户选择的题材、风格和模型适配器可以保留；具体项目名、特定人物形态不能成为通用任务的隐含要求。

## 数据与功能边界

| 工作区 | 维护内容 | 输出与审核 |
| --- | --- | --- |
| 剧本 | 构想、制作规格、全剧规划、分集正文 | 规划候选与正文候选分别审核；正文支持批量生成、差异对照、批量采用 |
| 角色设定 | 小传、演绎方式、外观、关系、音色 | 人物档案是项目设定来源；镜内表演由分镜保存 |
| 素材 | 人物、场景、道具的视觉资产与派生状态 | 复用已有实体 ID，图片不能替代文本设定 |
| 分镜与创作 | S 转场镜头、V 分镜视频、关键帧、生成产物 | 分镜 JSON 是镜头事实来源，模型能力只决定执行参数 |
| 空间预演 | 平面站位、轴线、路径和 3D 机位验证 | 可选验证工具；无几何证据时明确标记示意 |

## 剧本操作

填写输入和规格后生成规划，检查并确认规划，再选择分集生成正文。扩集保留已有框架；改写明确修改要求。正文生成写入候选批次，选中稿件经差异对照后统一采用。采用前比较原文与规划基线，发生冲突时保留候选并要求合并。失败不覆盖正式内容，也不重复生成已经完成的候选。

批次由服务端任务管理，浏览器关闭不终止正在执行的任务。分集 JSON 一次原子更新，版本快照保留历史；衍生文本副本刷新失败单独报告。所有完成、部分失败和失败均通过现有任务通知展示。

## 提示词分层

输出契约与任务事实优先；流程技能限定操作职责；创作方法指导剧情、节奏、表演；视觉风格限定图片与视频呈现。不同层分别注入，避免用画风改变剧情或以演员规则覆盖机位。模型负责提出内容，程序负责 ID、归属、引用和版本一致性。

## 验证范围

以临时项目和模拟模型响应验证批量候选、原子采用、版本冲突、角色维护和提示词契约；进行前端构建与局部页面检查。不以修改真实项目或批量付费生成为自动验收条件。
