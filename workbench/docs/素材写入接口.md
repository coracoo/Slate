# 素材写入接口

人物、场景、道具的正式档案分别保存在 `素材/人物.json`、`素材/场景.json`、`素材/道具.json`。镜头事实保存在分镜 JSON。图片索引仅登记媒体，不能恢复已经合并或删除的正式身份。

## 提交

`asset_repository.commit(project, documents, source, bases, operation_id)` 接收项目相对路径与文档内容。模型调用前读取 `bases`；提交时在项目事务锁内复核。单档编辑使用 `update_json`，在锁内读取并修改当前内容。

- 正式 ID、合并重定向、唯一完整别名命中时复用已有身份。
- 相似名称只产生候选，不能直接自动归并。
- `asset_revision` 仅在有效设定变化时递增；`field_sources` 记录字段来源与操作 ID。
- `operation_id` 重放返回原结果，不重复写入。
- 历史导入只补空字段；规划和补全保留人工锁定字段。
- 多文档提交先保存恢复日志，失败整批回滚；异常退出后下次写入先恢复。

事务记录、待确认候选保存在 `素材/.work/`。该目录不是第二份可编辑素材档案，不进入正式素材选择器。

## 批量审核

`GET /api/assets/visual-review` 返回当前设定、剧情依据、派生、历史复用和身份候选，以及审核版本。

`POST /api/assets/visual-review` 接收 `items` 和 `revision`：

- 字段编辑：`{id, patch}`。
- 身份决策：`{id, action, target?, label?, difference?, episodes?}`；`action` 为 `reuse`、`new`、`derived`。
- 派生需要名称及可见差异；`episodes` 填对应分集或场景，供下游选图。暂不采用的项目不提交。
- 身份候选附带关联文档 Diff；同批存在相互依赖的身份时一起确认。无关批次可分别处理。
- 所选变更涉及相同字段且意见不同，整批返回冲突；已采用内容不被覆盖。
- 弹窗打开后正式稿发生变化，旧提交被拒绝。重新打开时用已保存基线对比最新正式稿，保留候选未修改的字段；人工确认后才采用候选实际修改的部分。

前端入口统一为素材页“批量补齐与审核素材设定”，保留单素材详细编辑。旧 `/api/assets/reconcile` 仅作为兼容适配器，不设独立日常按钮。

## 下游与媒体

提交记录保存变化字段、设定版本、图像/音色影响和引用它的分镜文件。素材图沿用现有 `visual_source_hash` 判断输入是否变化，新生成图片额外保存 `settings_revision`。ChatGPT 队列刷新任务时同步更新来源版本，导入保留任务实际版本。

人物、场景、道具的派生均保存在母素材 `states`；生成时使用母图和可见差异。已有媒体文件及历史快照保留，当前设定更新不代表旧图片或视频已经重新生成。

子素材的 `parent_ref` 只指定两层展示归属，可选择人物、场景或道具母素材；
`derived_from` 单独指定生成参考，支持 `@kind:id#state_id` 精确派生图。
人工选择的展示归属不会被生成来源改写。明确解除归属保存 `parent_ref:null`，
保留剧情里的持有者 `owner`，但不再据此重新挂载。指定的派生图缺失时，须先生成或作为同批依赖生成，不回落到母图。

## 验证边界

自动验证使用临时项目覆盖身份复用、历史合并、派生引用、批量采用、版本冲突、幂等、写入失败及恢复。它不替代模型实际生成质量的验收。已有视频和镜头编辑仍由其原有创作契约管理，不由素材提交服务直接重写成片。
