# 角色工作区

角色设定统一承载人物小传、演绎方式、外观描绘、人物关系和音色绑定。左侧选角色，右侧维护资料；下方展开同一角色相关的镜头表演。镜头匹配支持人物 ID 与分镜显示名，继续沿用演员层原有主角范围。

## 数据与保护

权威数据仍为 `素材/人物.json` 的 `characters[]`，不另建平行人物库。新增 `biography` 保存自由正文小传；其余复用 `bio_*`、`acting`、`appearance`、`identity_anchor`、`sheet_prompt`、`relations[]` 和 `voice`。保存仅提交修改字段；嵌套对象保留未编辑扩展字段、音色绑定、派生状态及档案其他元数据。人工修改字段追加到 `locked_fields`，延续锚定层人工优先规则。

所有保存经过 `project_store.update_json`，必须携带 `expected_revision`，并以 `versions.snapshot` 保留原版。页面切换角色或项目时暂存文本草稿；离开页面或关闭窗口时提示未保存内容。绑定音色后的重新读取只在用户所改文本未被外部改变时更新草稿版本；冲突时保留草稿，不覆盖他人修改。

外观编辑按子字段保护，例如只修改五官时锁定 `appearance.face`，不阻止补齐发型、体型和服装。历史整对象 `appearance` 锁继续保留；若必填缺项被锁定，补全在调用模型前报告对应字段。

旁白只作为返回数据中的 `reserved: true` 合成行，仍由音色接口维护 `素材/音色/旁白.json`。角色文本接口拒绝旁白、未知字段和指向旁白或不存在角色的人物关系。

## 项目资料与镜内表演

项目角色资料是全剧基准。演员层从人物 `acting` 投影角色理解；`acting_context` 保留本分镜的目标、知情事实、关系状态与人工字段锁。项目资料保存不会写分镜、清除已采用 `performance` 或替换镜内人工理解。新生成的表现继续先进入候选，审核采用后才影响正式镜头。

原音色页与演员页增加 `embedded`、`selectedCharacterId`，统一页直接嵌入现有流程，继续使用原有音色和演员接口。演员嵌入还接受 `selectedCharacterName` 兼容不同的分镜人物 ID；只展示所选角色参与的镜头和相关候选。多人同镜仍按整镜生成与采用，以保存角色间互动。

## 接口

- `GET /api/characters?project=项目`：路由解析项目后调用 `character_profiles.state(project_dir)`，返回 `{ok, characters, revision}`。
- `POST /api/characters/save`：请求 `{project, character_id, patch, expected_revision}`，调用 `character_profiles.save(project_dir, character_id, patch, expected_revision=...)`，返回 `{ok, character, revision}`。版本冲突按既有约定返回 409，校验错误返回 400。

资料接口不调用模型。音色生成、表演生成仍只在用户点击相应操作时发起。测试使用临时项目验证字段保护、快照、并发版本冲突、旁白与关系边界，以及项目设定修改后原有镜头表演保持原样。

## 小传生成

剧本规划的设定阶段自动生成 `biography`，与演绎五项分别落盘。本页显示规划生成的小传并支持人工编辑；旧项目用剧本工作区的「补全规划缺项」补齐，已填写和保护字段不覆盖。小传是正文扩写的输入，不要求先生成正文。

## 外观设计与设定图

规划设定阶段同时起草外观设计。人类至少覆盖五官、发型、体型、服装；非人类覆盖物种、身体结构、辨识特征和综合外貌。已有原文证据与人工设定保留，无依据的补充放入 `appearance.proposals`，在角色页采用并保存后才用于正式生图。年龄、身高、腰臀围等不作为必填项，不自动编造测量值。

「补全规划缺项」会识别外观缺项，即使小传已完整也不会跳过；已有建议算完成设计草稿，不代表已采用。规划版本详情同时展示外观与待采用建议。连续补全没有减少缺项时停止并报告。

设定补全只处理当前分集、伏笔及其父素材依赖中的在用实体。按缺项工作量分批，每批最多四个实体；全新小传加形象设计通常每批两个。请求仅带全剧概要、精简身份索引与本批角色资料，只允许返回缺项。JSON 或字段校验失败时拆小批，单实体仍失败即停止；网络或鉴权失败不触发拆批。每个成功批次立即保存，下次从剩余缺项续跑；未引用的历史档案不自动删除。

人物母图、派生状态图、ComfyUI 与 ChatGPT 队列共用 `skill_lib` 中的五视图构图：正脸及颈部、45°脸及颈部、从颈部开始到脚底的正面全身、从颈部开始到脚底的侧面全身、含头部的背面全身。中文与英文均用正向取景范围描述。画风 Skill 只控制风格，不再定义另一套视角。

视觉素材注册表、提示词预览、本地生图与 ChatGPT 资产队列通过 `visual_asset_prompt.subject_prompt` 读取最新档案，不要求重新提炼全局素材。人物已有正式外观时，历史自动 `sheet_prompt` 不再参与母图；人工明确编辑的描绘作为补充保留。没有正式外观的历史档案继续兼容旧描绘。未采用建议不自动进入生图，原始描绘仍保存在档案中。

派生人物图先写 `look_diff` 的明确变化，再保留状态 `sheet_prompt` 的完整目标外观；冲突时明确变化优先。母图提供人物身份，编译器只补结构化生理特征，不重复自由文本身份锚点、母图服装或可能混有跨集道具的泛化辨识特征。状态名称不能代替生图指令。

每个派生必须对应一个确定时刻，写清服装、持物、伤情的变化及要替换的旧物。纯动作过程、立场改变、藏在衣内不可见的道具不要求另生人物图，交给分镜表现。上游设定不得把全剧不同阶段的装备堆入母图外观。历史状态若混写多个时刻，需要先确认目标外观；不会自动改写剧情或删除原图。

确认复用母图的旧状态保留原记录，并将 `output_asset_ref` 指向本角色母素材；素材图索引同步标记，派生列表及自动按集选图不再使用该旧派生图。原文件与历史快照保留。状态内的 `locked_fields` 保护人工确认的差异和复用关系，后续跨集提炼按字段合并，不能整条替换掉这些决定。

Qwen Image 2.1 参考图编辑使用编码节点返回的匹配潜空间画布，解码后等比缩放并居中裁切到请求尺寸；参考图宽高比差异较大时，边缘可能被裁切，人物设定图宜使用与目标一致的母图画幅。新生成仍使用独立随机种子，模型加载缓存不代表采样结果复用。

场景空间限制、动作位与道具使用边界随当前档案同步。素材图索引只补媒体信息，不得用旧出图提示词回填权威档案中已清空的描绘。前端编译预览与独立文本编辑分开，避免将合成提示词反复写回再叠加。

旧人物图描绘读取时归一化，生成前剥离旧构图后统一注入；历史档案可用 `character_profiles.normalize_sheets(project)` 带快照归一化母图与状态图。原外貌正文完整保留，不截断，不从模板推断人物外貌，不修改历史版本或已生成图片。

人物母图和派生图生成、ChatGPT 图片导入后，自动检查白底五视图的第3、4格；仍有头部时，用纯白圆形遮盖，原图保存到 `.versions`。正脸、45°脸和背面头部保留，已从颈部起框的视图跳过。定位不可靠时明确告警，并在素材图索引的 `head_mask` 中记录 `needs_review`。已处理 PNG 带像素校验标记，重复执行不再修改。

现有图片可用项目虚拟环境运行 `workbench/tools/character_sheet_mask.py <图片绝对路径>` 单独处理。
