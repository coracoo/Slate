# 角色音色资产与视频衔接

日期：2026-09-21。状态：三层创作台 v2 配套设计，尚未接入生产页面。

主方案：[三层视频创作台](2026-09-21-三层视频创作台设计.md)。本文件补齐“素材生成 → 音色绑定 → 人物引用 → 视频或台词配音 → 本地归档”的数据和实现边界。

## 1. 页面入口与职责

在“③素材生成”下增加“音色绑定”页签/子页 `/studio/asset/voices`：

- 左侧列当前项目人物母素材，显示头像、角色名、原有声音描述、已绑定音色和就绪状态；可筛选未绑定角色。
- 右侧为音色库：按已配置厂商/账户、语言、类型、标签和关键词筛选；“从 API 刷新”拉列表并缓存；每条可试听、查看详情、绑定到左侧当前角色。
- 右侧另一页签“AI 音色创作”：描述音高、质感、年龄感、口音、语速和情绪，填写试听文本，生成候选，试听后保存为音色资产，再绑定角色。
- 角色当前绑定在页底预览，明确显示资产名、厂商来源和本地样音。替换、解除绑定仅影响后续任务，历史语音/视频保留原版本。
- 素材页附“台词配音”入口：按分镜的 speaker 和台词生成本地语音素材。创作台移除语音 tab、手填 voice_id 和独立语音按钮；保留人物音色的只读显示和“去绑定”链接。
- 音乐仍是独立素材，当前创作台音乐入口保留，不混入角色音色库。

只把声音合成 API 的下拉框移到素材页不够：角色必须绑定工作台自己的音色资产，而不是每次生成再填写厂商 ID。

## 2. 已核实的厂商能力与限制

MiniMax 提供 `POST /v1/get_voice` 查询系统、复刻和文生音色；响应按音色类型返回 ID 和描述。文生/复刻音色需成功用于语音合成后才能在该列表查询到。因此新创建的候选不能仅因刷新列表暂时缺席就被删除。[官方音色查询](https://platform.minimax.cn/docs/api-reference/voice-management-get)

MiniMax 的同步 TTS 支持 `voice_setting.voice_id` 与语速、音高等设置，可以把试听文本转为实际音频并本地保存。音色列表不应被假定自带所有试听 URL；没有样音时由用户点击生成一次试听，再复用缓存。[官方语音接口](https://platform.minimax.cn/docs/api-reference/speech-t2a-http)

AI 音色创作在产品上对应“音色设计”，不是复刻用户上传的人声。本次已定位官方音色设计文档入口，但页面正文抓取超时；具体请求字段、候选有效期和激活规则必须在适配实现时以官方契约和实际响应核验，不在方案中猜定天数或宣称接口已跑通。[官方音色设计入口](https://platform.minimax.cn/docs/api-reference/voice-design-design)

优先接 MiniMax，其他厂商用能力表逐项开放 `list_voices / synthesize_preview / design_voice / synthesize_speech`。没有 API 的能力显示不支持；不把普通语言模型生成的“声音描述”当作已生成音色。Agent Plan、普通 API、区域和账户不可自动互换。

## 3. 本地数据契约

### 3.1 人物资产只保存绑定指针

`素材/人物.json` 的角色条目新增：

```json
{
  "id": "baixiaozhuxu",
  "voice": "原有文字声音描述，保留作为选型或 AI 设计建议",
  "voice_binding": {"voice_asset_id": "voice_稳定ID", "revision": 2}
}
```

声音描述不是 voice_id。原有角色文件没有绑定时，显示“未绑定”，不从名称推断厂商音色。状态/服装子素材默认继承人物母素材的绑定；有明确变声需求才另行建立声音版本，不因换衣自动换音色。人物提炼、重提炼、编辑和合并必须保留或显式复核绑定，不能由 LLM 返回空字段覆盖。

### 3.2 音色索引：`素材/音色/音色库.json`

```json
{
  "schema_version": 1,
  "voices": {
    "voice_稳定ID": {
      "name": "蛛绪 · 清亮少女声",
      "current_revision": 2,
      "revisions": {
        "2": {
          "origin": "provider_system",
          "vendor_profile_id": "minimax_本机账户配置ID",
          "provider_voice_id": "真实厂商返回ID",
          "language": "zh-CN",
          "description": "清亮，轻快，略带紧张感",
          "synthesis_defaults": {"model": "所选语音模型", "speed": 1, "pitch": 0},
          "availability": "verified",
          "provider_expires_at": null,
          "verified_at": "ISO时间",
          "sample": {
            "path": "素材/音色/voice_稳定ID/r002/sample.wav",
            "sha256": "实际音频哈希",
            "text": "固定试听文本",
            "duration_seconds": 8.4
          },
          "design_prompt": null,
          "creation_job_id": null
        }
      }
    }
  }
}
```

示例不是厂商请求 JSON。`vendor_profile_id` 指向本机已有配置及账户身份；索引里不存密钥。更换账户后重新核验可用性，不因为 provider_voice_id 字符相同就认为是同一音色。每个 revision 不可变；人物绑定固定版本，换音色由显式“绑定”操作完成。

### 3.3 存储布局

```text
projects/<项目>/
├─ 素材/
│  ├─ 人物.json                         # 角色 → 音色资产版本
│  ├─ 音色/
│  │  ├─ 音色库.json                    # 资产元数据，正式索引
│  │  └─ voice_<id>/r002/
│  │     ├─ sample.wav                  # 标准化试听/声音参考
│  │     ├─ original.<实际格式>         # 原始返回音频，保留
│  │     └─ provenance.json             # 设计/试听来源和参数，无密钥
│  ├─ 语音/<角色ID>/<item_id>.wav       # 正式台词配音，和音色样本分开
│  ├─ 视频衔接/<来源item_id>/           # FFmpeg 抽帧与 Vision 记录
│  └─ 生成媒体.json                     # 可浏览的派生产出索引
└─ 创作/<item_id>/                     # 生成请求快照与原始产出
```

厂商全量列表是可再生缓存，存 `workbench/cache/voices/<profile_id>/catalog.json`，不把几百个未采用音色灌入每个项目。项目只入库已保存/绑定的音色和候选所需资料。缓存失败可看上次列表，显示更新时间；不能清空已有项目绑定。

原始音频按实际编码扩展名保存，FFmpeg 转换试听版本并用 ffprobe 验证时长、采样率与非空可播放性；无需伪造 wav 扩展名。文件先临时写入再原子替换，成功后更新索引。重试本地保存不重新生成云端音色。

本地保存的是音色元数据、真实样音和配音结果，不是下载了云端声音模型权重。离线仍能试听、播放与合成已有素材；重新合成语音仍取决于原厂商音色可用性。

## 4. API 获取、试听与 AI 创作流程

### 获取和试听

1. 按所选配置调用音色列表接口，缓存成功结果及时间。鉴权失败提示该配置问题，不换另一账户。
2. 试听优先使用已落盘样音；没有时，“生成试听”提交短文本 TTS job，返回后标准化保存。只有用户触发才生成，不为整个列表自动调用 TTS。
3. 缓存键包括 profile、voice_id、模型、试听文本和声音参数，避免改音高后仍播旧音频。UI 明确区分“播放已有试听”和“生成试听”。
4. 试听本地成功且云端 ID 已验证后可绑定。只有声音文字、空文件或失败 URL 的条目不显示“可用于参考”。

### AI 音色创作

`设计描述 → 创建候选 job → 保存返回 ID 与样音 → 用户试听 → 验证可用于 TTS → 保存音色版本 → 绑定角色`

- 新候选先保存创建结果，状态为 `candidate`；已有真实样音可试听，但可用性未核验时不标 `verified`。
- 候选在列表暂不可查询与创建失败不是同一状态。依据厂商契约完成必要的 TTS 验证/激活；有效期如有返回就记录，无法确定则标未知，不能编造“永久可用”。
- 非可恢复的创建请求超时标记提交结果待核对，禁止自动循环再创；列表刷新、试听缓存写入、绑定失败各自单独重试。
- “试听通过”是用户选用判断，不用 ASR 能转录就声称音色保真。AI 设计不会自动覆盖角色现有绑定。

## 5. 人物引用统一解析音色

人物引用入口始终是 `@character:<id>`；统一解析器展开以下逻辑包：

```text
人物身份 → 当前外观/状态参考图
         → voice_binding → 音色资产固定版本
                           ├─ 厂商语音 ID + 合成参数
                           └─ 本地样音 + 哈希 + 声音描述
```

可读 token 为 `@voice:<voice_asset_id>:r002`，界面显示“白咲的音色”。引用音色不新增一个画面人物，也不把音色资产当作图片上传。

| 消费端 | 编译行为 |
|---|---|
| S 关键帧/其他生图 | 保留角色的逻辑绑定元数据，仅编译视觉参考；不上传音频、不把声音描述塞进外观提示词 |
| 原生 TTS | 使用匹配厂商账户的 provider_voice_id，逐角色生成台词，冻结音色 revision |
| 支持音频参考的视频模型 | 上传真实本地样音，建立“角色图片 → 角色 → 音频编号”的映射；描述仅参考音色，不复述试听文本或带入样本 BGM |
| 不支持音频参考的视频模型 | 显示不能直接继承音色。用户可选择独立 TTS 后期配音，或换支持的模型；不声称一个外部 voice_id 就能控制该视频模型 |
| 不包含对白的角色镜头 | 角色绑定仍随引用解析，但不自动上传多余样音、要求人物说话或生成额外台词 |

音频上传顺序单独编号，不与图片序号混为一个列表。人物、样音和台词的对应关系由稳定 ID 编译，不能由 LLM 自己猜。是否有对白以 `lines[].speaker` 为准；有对白且要求统一音色时，缺失绑定/样音阻断该声音模式并提供去绑定入口。

首帧强制续接和声音参考的组合也要检查目标模型允许的混合输入，不能为了保留 first_frame 静默丢掉角色音色。

Seedance 2.5 官方指南列明主体图与主体音色音频组合，并建议明确图片和音频之间的对应关系；这不代表其他视频厂商同样支持，也不保证生成音色与原样本完全相同。[官方参考说明](https://docs.volcengine.com/docs/ark/seedance-2-5-prompt-guide?lang=zh)

## 6. 配音落盘、历史和迁移

- 台词文本、speaker、镜头顺序继续来自原分镜 `shots[].lines`，不在音色库复制剧本正文；稳定 line_id 用于逐句追踪。
- 配音 item 保存 board、shot_id、line_id、speaker、voice_asset_id/revision、合成文本与参数、实际时长、音频哈希；后续用户换音色只把受影响的待用配音标为需更新，原文件不覆盖。
- 配音和视频时长不符时明确提示裁剪、停顿或节奏调整；不得静默截断台词。集合成只选一种主对白来源，避免模型原声和 TTS 重叠。纯音轨叠加不等同于完成口型同步；需要同步时另选经过验证的口型处理流程。
- `narrator` 仍是画外声音轨，不建人物素材。若有旁白，提供独立“画外音”绑定区，不能加入演员外观/生图引用。
- 旧 speech 条目保留，只迁移可确定的角色、厂商、voice_id 关系；同角色历史存在多个音色时不按最后一条武断覆盖，展示候选供选用。
- 项目导出包含音色索引、绑定、样音、正式配音及来源信息，不导出凭据；导入后本地音频可播放，云端音色 ID 标记待账户核验。绑定文件、音色版本、语音原件不能因清理画廊历史而删除。
- 人物删除/重命名与音色解除绑定采用现有版本快照；仍被任务引用的音色保留归档版本。跨集角色用同一人物 ID 解析，不能按角色显示名称绑定。

## 7. 服务与接口边界

- `voice_assets.py`：项目音色索引、固定 revision、人物绑定与迁移；使用 project_store 原子更新和 expected_revision。
- `voice_providers.py`：厂商能力、拉音色、设计音色、试听和 TTS；复用 VendorClient 的配置读取、错误处理，不在 Vue 内调用带密钥 API。
- `voice_reference_resolver.py`：统一展开角色音色；由 prompt_assembler、S/V 请求编译和台词配音共用。
- `video_continuity.py`：尾帧、Vision 描述、版本与依赖；与音色引用在 video_request_compiler 汇合。
- `VoiceBindingView`：人物列表、音色库、AI 候选、绑定预览、台词配音入口；创作台只读音色摘要。

拟定接口：

- `GET /api/voices?project&vendor_profile_id`：项目音色及缓存目录；读请求不触发 TTS。
- `POST /api/voices/refresh`：刷新厂商目录。
- `POST /api/voices/preview`、`POST /api/voices/design`：异步 job；具备 request_nonce 与不确定提交状态。
- `POST /api/voices/save`：保存候选为固定音色版本，引用已完成 job，不接受客户端伪造 verified。
- `POST /api/voices/bind`：角色绑定/解除，携带 expected_revision。
- `POST /api/speech/render`：按明确的剧本/镜头/台词范围生成配音；源字段从分镜读取，复用现有 audio executor 和归档。

## 8. 分步实施与验收

1. **音色资产与只读解析**：索引、人物绑定、重提炼保护、迁移；生图的音频隔离与视频引用数据先用 fixture 验证。
2. **音色库和试听**：MiniMax 拉取、单条试听、缓存、绑定页面；API 不可用仍可访问本地样音。
3. **AI 音色候选**：核实官方请求/响应后接创建、试听、可用性核验、保存；无法确认时暂停候选，不重复创建。
4. **视频/配音消费**：一位角色一个声音参考先验收，再验证多人声音映射；补齐 S/V 首帧混合输入限制和本地语音合成。

必须覆盖：API 空列表不清空项目绑定；账户改变不混用 ID；列表无试听 URL 仍能按需生成；创建候选未激活不丢失；只改一个角色影响范围可追踪；后续人物引用自动带上同一声音版本；纯图请求不带音频；视频不支持音色参考时明确说明；刷新/重复提交不产生第二次音色创建；本地音频可播放且元数据与真实格式相符。
